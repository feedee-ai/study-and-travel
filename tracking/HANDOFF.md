# Передача: пиксель Meta + Conversions API на WordPress

## Проблема
Заявки с сайта приходят в Telegram, а в Facebook часть из них не видна, без закономерности.
Причина: Lead стоит на странице «Спасибо», куда человек попадает только после клика «ОК» в окне
после отправки. Не нажал ОК, закрыл вкладку, iPhone/адблок срезал пиксель — события нет.
В Events Manager подключение отмечено «Conversions API · Только в браузере»: с сервера ничего не идёт.

## Решения (согласованы с пользователем)
- Один пиксель на все лендинги: **Study and Travel 2024, ID 1146010926423221**.
- Заявка на обычных лендингах → `Lead`. Регистрация на `/webinar*` → `CompleteRegistration` (в тот же пиксель).
- Отдельный вебинарный пиксель пока **не трогаем**: пусть работает параллельно, пока пользователь
  не переключит вебинарные кампании на основной пиксель. Снять потом — только по его «да».
- Клик в Telegram лидом не считается, событие Contact не нужно.
- Lead — в момент приёма формы: сервер (CAPI) + браузер после успешной отправки, общий `event_id`.
- Кнопок «сразу в Telegram» в рекламе нет — все лиды идут через формы.

## Доступы (переменные среды)
`WP_URL`, `WP_USER`, `WP_APP_PASSWORD` (пароль приложения WP), `META_CAPI_TOKEN`.
Сеть: домен сайта и `graph.facebook.com` в Allowed domains. Плагин Code Snippets пользователь ставит сам.
Токены и пароли в чат не просить и не коммитить.

## Код
`tracking/st-meta-tracking.php` — готовый сниппет (PHP-синтаксис и JS проверены, на сайте ещё не стоял):
базовый пиксель, свои `_fbc/_fbp`, UTM в cookie на 90 дней, скрытые поля `st_*` в каждую форму,
браузерное событие после успешной отправки (CF7 / Elementor Pro / WPForms), CAPI на серверных хуках тех же
плагинов, лог отправок `GET /wp-json/st/v1/capi-log` (только админ).

## План для новой сессии
1. Проверить env и доступ: `curl -u "$WP_USER:$WP_APP_PASSWORD" "$WP_URL/wp-json/wp/v2/users/me"`.
2. Аудит: HTML главной, каждого лендинга и `/webinar` — сколько раз грузится `fbevents.js`, какие ID и
   события, откуда стоит текущий пиксель (плагин, тема, GTM, вставка в Elementor), чем сделаны формы,
   как заявка уходит в Telegram (плагин на сервере или JS прямо в api.telegram.org — тогда серверного
   хука нет, нужен свой адаптер). Список плагинов: `/wp-json/wp/v2/plugins`.
3. Подогнать сниппет под реальные формы (адаптер, если форма нестандартная; `window.stTrackSuccess(form)`).
   Проверить `ST_GRAPH_VER` на актуальность; выставить `ST_PHONE_CC` по стране аудитории.
4. Убрать старый Lead со страницы «Спасибо» и дубли базового кода основного пикселя
   (иначе двойной счёт: старый Lead без event_id не склеится). Вебинарный пиксель не трогать.
5. Залить сниппет через REST Code Snippets (`/wp-json/code-snippets/v1/snippets`), токен подставить из
   `$META_CAPI_TOKEN` при заливке, `ST_TEST_CODE` = код из Test Events.
6. Тестовая заявка на каждом лендинге и на `/webinar`: событие в Test Events (браузер + сервер,
   «дедуплицировано»), запись в `/wp-json/st/v1/capi-log` с кодом 200, сообщение в Telegram.
7. Обнулить `ST_TEST_CODE`, показать пользователю результат.
8. Желательно: `event_id` и UTM в сообщение в Telegram, чтобы сверять заявки один к одному.
